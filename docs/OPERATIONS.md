# คู่มือดูแลระบบ (Operations)

เอกสารนี้สำหรับผู้ดูแลที่ "นานๆ ดูที" — ตอบว่าอะไรอยู่ที่ไหน ทำอะไรปีละครั้ง และแก้ปัญหาที่พบบ่อยอย่างไร
(สถาปัตยกรรมละเอียดอยู่ที่ `docs/GAS-DESIGN.md`, กติกาและหน้าเว็บอยู่ที่ `docs/SPEC.md`)

## 1. ภาพรวมว่าอะไรอยู่ที่ไหน

| ส่วน | อยู่ที่ | หมายเหตุ |
|---|---|---|
| หน้าเว็บ | GitHub Pages ของ repo นี้ | อัปเดตอัตโนมัติเมื่อ push เข้า `main` (`.github/workflows/deploy.yml`) |
| โค้ดหลังบ้าน | Google Apps Script (โฟลเดอร์ `gas/`) | อัปเดตด้วย `clasp push` + `clasp deploy` (ข้อ 5) |
| ข้อมูลทีม/ตั้งค่า | Google Sheets ส่วนตัว "SciTech Registration — DATA" | **ห้ามแชร์ให้ใคร** เปิดดูลิงก์ได้จาก `showSetup()` ใน Apps Script |
| ไฟล์ที่ทีมส่ง / ไฟล์สำรอง | Google Drive โฟลเดอร์ `team-files`, `backups` (ส่วนตัว) | เจ้าของ = บัญชี Google ที่รัน `setup()` |
| โลโก้ ภาพพื้นหลัง PDF ภาพกิจกรรม | Drive โฟลเดอร์ `public-assets`, `gallery` (ใครมีลิงก์ดูได้) | |
| ความลับ (pepper รหัส PIN, แฮชรหัสผ่าน Admin, TOTP) | **Script Properties** ของ Apps Script เท่านั้น | ไม่อยู่ใน repo/เว็บ/ชีต |
| URL ของหลังบ้าน | ตัวแปร `VITE_GAS_URL` ของ repo (Settings → Secrets and variables → Actions → Variables) | ลงท้าย `/exec` เป็นข้อมูลสาธารณะ |

หน้าเว็บ: `#/` หน้าหลัก · `#/gallery` ภาพกิจกรรม · `#/apply` สมัคร · `#/status` ตรวจสอบ · `#/admin` ผู้ดูแล

## 2. งานประจำปี (ลำดับที่แนะนำ)

1. **เปิดปีใหม่**: Admin → "ปี/รอบการจัด" → สร้างปีใหม่ (คัดลอกข้อความและช่องส่งไฟล์ ปิดรับสมัครไว้ก่อน) → ตั้งชื่อ ภาพพื้นหลัง PDF กำหนดการ ที่แท็บ "เนื้อหาหน้าเว็บ" → **ให้ฝ่ายกฎหมาย/DPO ตรวจข้อความ PDPA** → ตั้งเป็น "ปีปัจจุบัน"
2. **เปิดรับสมัคร**: "ปี/รอบการจัด" → เลือกโหมด `ตามช่วงเวลา` พร้อมวันเวลาเปิด/ปิด (เวลาไทย) หรือ `เปิดบังคับ`/`ปิดบังคับ` — เซิร์ฟเวอร์ใช้นาฬิกาของ Google ตัดสินเสมอ
3. **ระหว่างรับสมัคร**: ดูแท็บ "รายชื่อทีม" ตรวจ/อนุมัติ แก้ข้อมูลแทนทีม ตั้ง PIN ใหม่ให้ทีมที่ลืม อ่านข้อความถึงกรรมการ ส่งออก CSV
3.1 **เอกสาร/แบบฟอร์มให้ทีมโหลด**: แท็บ "เอกสารให้ทีม" ใส่ชื่อเอกสาร เลือกไฟล์ กดอัปโหลด (กด "+ เพิ่มไฟล์" เพื่อเพิ่มหลายไฟล์) ทีมจะเห็นในหน้า "ตรวจสอบการสมัคร" หลังกรอกชื่อทีมและ PIN เท่านั้น — ไฟล์อยู่ในโฟลเดอร์ `public-assets` (ใครมีลิงก์เปิดได้) จึงห้ามใส่เอกสารลับ
4. **เปิดช่องส่งไฟล์**: แท็บ "ช่องส่งไฟล์" กำหนดชนิดไฟล์ ขนาด กำหนดส่ง แล้วกดเปิด
5. **หลังงาน**: อัปโหลดภาพที่แท็บ "ภาพกิจกรรม" (ย่อให้อัตโนมัติ) หรือใส่ลิงก์อัลบั้มภายนอกถ้าภาพเยอะ
6. **สิ้นสุดการประกวด → ลบข้อมูลส่วนบุคคลตามนโยบาย PDPA**: ปิดรับสมัคร → แท็บ "สำรอง/รีเซ็ต" → **สำรองข้อมูล** (ตรวจว่าโฟลเดอร์ใน Drive เปิดได้และไฟล์ครบ) → รีเซ็ต
   (ต้องลงทะเบียนแอป Authenticator ที่แท็บ "บัญชีของฉัน" ไว้ก่อน; ต้องเข้าสู่ระบบไม่เกิน 10 นาที, พิมพ์ `PURGE <ปี>`, กรอกรหัสผ่านซ้ำ และรหัส 6 หลัก)
   - `ทำให้ไม่ระบุตัวตน` (แนะนำ): เก็บชื่อทีม/เลขที่ใบสมัคร/สถานะ ลบข้อมูลส่วนตัวและไฟล์
   - `ลบทั้งหมด`: ลบทีมของปีนั้นทั้งหมด
   - ไฟล์ที่ทีมส่งถูกลบถาวร ไม่ผ่านถังขยะ ภาพกิจกรรม/การตั้งค่า/ปีอื่นไม่ถูกแตะ
7. **ไฟล์สำรองเก่า**: ระบบไม่ลบให้ — กำหนดระยะเวลาเก็บตามนโยบายของมหาวิทยาลัย แล้วลบโฟลเดอร์ใน `backups` ด้วยมือเมื่อครบกำหนด

## 3. ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| ลืมรหัสผ่าน Admin | Apps Script → Project Settings → Script properties เพิ่ม `NEW_ADMIN_ID` และ `NEW_ADMIN_PASSWORD` (≥ 12 ตัว) → เปิดไฟล์ `Admin.gs` เลือกฟังก์ชัน `createAdmin` → Run (ตั้งรหัสใหม่ให้ ID เดิม และลบ property ชั่วคราวให้เอง) |
| ล็อกอินผิดหลายครั้งแล้วเข้าไม่ได้ | ระบบล็อกการล็อกอินชั่วคราว 15 นาที (นับรวมทั้งระบบ) — รอแล้วลองใหม่ |
| ทำแอป Authenticator หาย | เพิ่ม `NEW_ADMIN_ID` เป็น ID นั้น → รัน `resetAdminTotp` → ล็อกอินแล้วลงทะเบียนใหม่ที่ "บัญชีของฉัน" |
| ทีมลืม PIN | แท็บ "รายชื่อทีม" → เลือกทีม → ตั้ง PIN ใหม่ (ปลดล็อกการเดา PIN ด้วย) แล้วแจ้งทีมทางช่องทางส่วนตัว |
| อัปโหลดไม่ได้ ขึ้น "เว็บนี้ยังไม่ได้รับอนุญาต" | Script property `ALLOWED_ORIGINS` ต้องมี `https://<user>.github.io` (คั่นด้วย `,` ได้หลายค่า เช่น `http://localhost:5173,https://ncrmutr.github.io`) |
| "ระบบกำลังประมวลผลคำขออื่นอยู่" บ่อย | มีคนสมัคร/อัปโหลดพร้อมกันมาก หน้าเว็บลองซ้ำให้เอง 3 ครั้ง ถ้ายังไม่ได้ให้รอสักครู่ |
| ภาพ/โลโก้ไม่ขึ้น | โฟลเดอร์ `public-assets`/`gallery` ต้องเป็น "ใครมีลิงก์ดูได้" (รัน `setup()` ซ้ำเพื่อให้ตั้งค่าให้ใหม่ได้ ปลอดภัย ไม่ทับข้อมูล) |
| รูปหรือ PDF จาก Drive ไม่ขึ้น ทั้งที่ลิงก์เปิดได้ | อาจถูก Content-Security-Policy บล็อก: เปิด Console ของเบราว์เซอร์ (F12) ดูข้อความ "Refused to load … Content Security Policy" แล้วเพิ่มโดเมนที่ถูกบล็อกใน `vite.config.js` (`img-src` / `frame-src`) แล้ว push |
| หน้าเว็บไม่เปลี่ยนหลังแก้ใน Admin | หน้าสาธารณะแคชไว้ไม่เกิน ~1 นาที |
| โควตา Google เต็ม | Apps Script/Drive มีโควตารายวัน (ฟรีบัญชีองค์กรสูงกว่าบัญชีส่วนตัว) ดู Apps Script → Executions และ Drive → Storage |

## 4. ความปลอดภัยที่ต้องรู้

- ห้ามใส่รหัสผ่าน/ID Admin/โทเค็นลงในไฟล์ใดๆ ของโปรเจกต์ — ตั้งผ่าน Script properties เท่านั้น และตัวแปรชั่วคราวจะถูกลบเองหลังรันฟังก์ชัน
- แชร์ Spreadsheet และโฟลเดอร์ `team-files`/`backups` ให้ผู้ดูแลเท่าที่จำเป็น (ผู้ที่แก้ชีตได้โดยตรงข้ามกติกาทั้งหมดได้)
- ผู้ดูแลที่เปิดไฟล์ของทีมจากหน้า Admin ต้องล็อกอินบัญชี Google เจ้าของระบบในเบราว์เซอร์เดียวกัน
- หน้าเว็บมี Content-Security-Policy (สร้างตอน build โดย `vite.config.js`) อนุญาตเฉพาะสคริปต์ของเว็บเอง และการเชื่อมต่อไปที่ Apps Script/Google Drive; ถ้าเพิ่มบริการภายนอกใหม่ต้องเพิ่มโดเมนในไฟล์นี้ด้วย
- ตัวนับล็อก (PIN, รหัสผ่าน Admin) และ rate limit เป็นแบบรวมทั้งระบบ เพราะ Apps Script มองไม่เห็น IP ผู้เรียก — ช่วงปิดรับสมัครควรมีคนเฝ้าดู
- ย้ายความเป็นเจ้าของ: โปรเจกต์ Apps Script, Spreadsheet และโฟลเดอร์ Drive อยู่ใต้บัญชี Google เดียว (ควรเป็นบัญชีองค์กรหรือบัญชีกลาง ไม่ใช่บัญชีส่วนตัวของคนที่อาจลาออก) — ก่อนส่งมอบให้ย้ายความเป็นเจ้าของ Spreadsheet/โฟลเดอร์/สคริปต์ไปบัญชีใหม่ แล้วรัน `setup()` และ `createAdmin` ด้วยบัญชีนั้น

## 5. แก้ไขและอัปเดตโค้ด

เครื่องมือ: Node.js 20+, Git, `gh`, และ `clasp` (มากับ `npx clasp`) — `clasp login` ด้วยบัญชีเจ้าของสคริปต์ (ไฟล์ `.clasp.json` ถูก git ignore: สร้างด้วย `npx clasp clone <scriptId> --rootDir gas` หรือ `npx clasp create`)

```
npm install
cp .env.example .env.local     # ใส่ VITE_GAS_URL ของ Web App
npm run dev                    # เว็บบนเครื่อง http://localhost:5173
npm test                       # ทดสอบกติกาของ gas/*.gs บนชีต/Drive จำลอง (ไม่ต้องต่อ Google)
npm run build                  # ผลลัพธ์ใน dist/ (มี CSP)
```

- **หน้าเว็บ**: push เข้า `main` → GitHub Actions build และเผยแพร่เอง (ตัวแปร `VITE_GAS_URL` ตั้งที่ repo)
- **หลังบ้าน**: `npx clasp push --force` แล้ว
  `npx clasp deploy --deploymentId <ID ของ deployment เดิม> --description "..."`
  **อย่าสร้าง deployment ใหม่ และอย่าเก็บ/ลบ deployment เดิมใน Manage deployments** — URL `/exec` จะเปลี่ยน/ใช้ไม่ได้ (ถ้าเกิดขึ้นต้องแก้ตัวแปร `VITE_GAS_URL` ของ repo แล้ว re-run workflow)
- ตรวจเวอร์ชันที่รันอยู่: เปิด URL `/exec` ในเบราว์เซอร์ หรือส่งคำสั่ง `ping` (ตอบ `version`)
- อย่าทำให้ล็อกอิน/ล็อก PIN/rate limit/script lock/guard ของการรีเซ็ตหย่อนลงเพื่อความสะดวก (ดู `CLAUDE.md`)

## 6. สิ่งที่ยังเป็นรายการเปิด (ต้องตัดสินใจโดยมหาวิทยาลัย/เจ้าของ)

1. ระยะเวลาเก็บข้อมูลที่ไม่ระบุตัวตนและไฟล์สำรอง ตามนโยบาย PDPA
2. ข้อความ PDPA (ตอนนี้เป็น placeholder) ต้องผ่านการตรวจโดยฝ่ายกฎหมาย/DPO และต้องยืนยันว่าเก็บข้อมูลบน Google Sheets/Drive ได้
3. ภาพกิจกรรมที่มีใบหน้าคน ต้องมีประกาศ/ความยินยอมของตัวเองที่งาน
4. โควตา Drive: ภาพชุดใหญ่ใช้ลิงก์อัลบั้มภายนอก
5. Phase 2 (ยังไม่ได้สร้าง): ผลการประกวด กรรมการ กำหนดการละเอียด ข่าวต่อปี
6. ฟอนต์ IBM Plex Sans Thai โหลดจาก Google Fonts (ผู้เข้าเว็บส่ง IP ไปที่ Google) — ถ้าต้องการไม่พึ่งบริการภายนอก ให้โฮสต์ฟอนต์เอง
